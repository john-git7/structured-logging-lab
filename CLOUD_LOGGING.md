# Cloud Logging Mapping

Converting our application's text logs to structured JSON drastically improves observability in cloud logging services (like Google Cloud Logging, AWS CloudWatch, Datadog, or Grafana Loki).

Here is how our newly structured fields map to powerful cloud capabilities:

- **`ts` (Timestamp)**: Cloud loggers automatically parse standard ISO-8601 timestamps, ensuring events are chronologically sorted and enabling precise time-range filtering during incidents.
- **`level` (Severity)**: Instead of regex-matching the word "Error", the JSON `level` field maps natively to the cloud logger’s severity flags. This enables filtering (e.g., `severity >= WARNING`) and automated alerting (e.g., "Page the on-call if `level: error` exceeds 10 per minute").
- **`reqId` (Request ID / Correlation ID)**: This is the most crucial addition. Cloud loggers allow searching by custom fields. By entering `jsonPayload.reqId="1234-abcd"`, you filter the ocean of logs down to the exact 5-10 lines generated by that single failing request, across all internal service boundaries.
- **`msg` & `extra` (Context)**: The string message gives humans a quick summary, while additional keys (like `product_id` or `err.message`) are indexed by the cloud provider, allowing advanced analytical queries without string parsing.

Structured logging turns text into queryable data.
